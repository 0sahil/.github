# Contributing

Thanks for your interest in contributing! Bug reports, ideas, documentation fixes and code are all welcome.

Contributions are [released](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service#6-contributions-under-repository-license) to the public under the repository's open source license.

This project is released with a [Code of Conduct](CODE_OF_CONDUCT.md). By participating, you agree to abide by its terms.

If the repository has its own contributing guide or development docs, they take precedence over this file.

## Reporting issues

- Search the existing issues, including closed ones, before opening a new one.
- Use the issue form and include as much detail as you can: the version you're using, your operating system or device, steps to reproduce, and what you expected to happen.
- Keep each issue to one bug or one idea.
- Don't report security vulnerabilities in public issues. See the [security policy](SECURITY.md).

## Submitting a pull request

1. For anything beyond a small fix, open an issue first to discuss the change. This avoids work on something that won't be merged.
2. Fork and clone the repository.
3. Create a new branch from the default branch: `git checkout -b my-branch-name`.
4. Make your change, add tests, and make sure the tests pass. The README explains how to build and test the project.
5. Push to your fork and [open a pull request](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/proposing-changes-to-your-work-with-pull-requests/creating-a-pull-request-from-a-fork).
6. Wait for a review. Feedback may ask for changes before the pull request is merged.

A few things that make a pull request more likely to be accepted:

- Follow the project's existing code style.
- Write tests for your change.
- Keep the change focused. Unrelated changes belong in separate pull requests.
- Write a [good commit message](https://cbea.ms/git-commit/).
- Reference the issue it resolves in the description, for example `Fixes #123`.
- Leave "Allow edits from maintainers" checked so small fixes can be made directly.
