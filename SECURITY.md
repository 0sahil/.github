# Security Policy

## Supported Versions

Security fixes are made for the latest release of each project only. Please make sure you can reproduce the issue on the latest version before reporting it.

| Version | Supported |
| ------- | ------------------ |
| Latest release | :white_check_mark: |
| Older releases | :x: |

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues, discussions or pull requests.**

Instead, report them privately:

- Use GitHub's private vulnerability reporting: open the repository's **Security** tab and click **Report a vulnerability**. See [Privately reporting a security vulnerability](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability).
- If that option isn't available for the repository, email 0sahil.dev@gmail.com with "Security" and the repository name in the subject.

Please include as much of the following as you can:

- The type of issue (for example data exposure, injection, or authentication bypass)
- The affected repository, version, and source files (tag, branch, commit or direct URL)
- Any special configuration required to reproduce the issue
- Step-by-step instructions to reproduce the issue
- Proof-of-concept or exploit code, if possible
- The impact of the issue, including how an attacker might exploit it

### What to expect

- An acknowledgement within 7 days.
- An update on the assessment and, if the report is accepted, a plan for a fix.
- A fix released as soon as practical, followed by a security advisory crediting you, unless you prefer to stay anonymous.
- If the report is declined, an explanation of why.

Please give a reasonable amount of time to release a fix before disclosing the issue publicly.
